# Vulnerability Reporting Reference & Templates

A bug is only as valuable as the report describing it. Professional bug bounty triagers and security engineering teams evaluate findings based on clarity, reproducibility, and accurate impact assessment.

---

## 🎯 Reporting Standards

1. **Clarity**: State the vulnerability type, target asset, and technical severity in the first paragraph.
2. **Reproducibility**: Provide step-by-step instructions that allow a triager to replicate the finding in under 5 minutes without guesswork.
3. **Evidence**: Include sanitized HTTP request/response proofs-of-concept and screenshots where applicable.
4. **Professionalism**: Maintain an objective, constructive tone. Avoid exaggerated impact claims (e.g., claiming a minor info leak allows "full system takeover").
